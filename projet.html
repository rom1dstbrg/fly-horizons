2026-09-08 · Interface

Masse & centrage : flux vertical numéroté, tous les champs gardés

Contexte
La page M&B « n'a aucune structure » (Romain) : la carte « Chargement » mélangeait avion+date, les poids et les boutons enregistrer/PDF ; les perfs étaient un îlot en bas ; aucun verdict unique (1 centrage + 3 perfs éparpillés).
Décision
Flux vertical en 4 sections numérotées, dans l'ordre du travail : 1 Le vol (avion, date) · 2 Chargement (saisie à gauche, tableau + graphe CG + verdict centrage à droite) · 3 Performances · 4 Verdict & feuille (GO/NO-GO combiné + libellé + boutons). Tous les champs actuels conservés, seule la mise en page change. Calcul / PDF / METAR intacts.
Alternatives écartées
Saisie gauche / résultats collants à droite (« config + aperçu ») ; onglets Chargement / Perfs / Verdict — les deux jugés moins lisibles qu'un flux linéaire pour ce type de feuille.
Conséquences
1er jet livré (7943759), à valider dans le navigateur ; ajustements fins attendus.

2026-09-08 · Espace pilote

Option 3 — le pilote gère uniquement ses propres annonces

Contexte
En codant le modèle de paiement (bloc D), le blocage légal de fond a émergé. Assigner une réservation payée de Romain à un pilote tiers, où le client couvre le coût direct du vol (avion + carburant + taxes) : le pilote ne porte aucune part réelle → ce n'est plus du partage de frais → transport commercial sans AOC → illégal, et c'est le pilote qui risque sa licence.
Décision
Le pilote gère uniquement ses propres annonces (annonces_pilote) : il organise le vol, fixe le prix, partage avec les occupants qu'il amène (le vrai cas NCO.GEN.104). Romain ne refile pas ses bookings à des pilotes.
Alternatives écartées
(A) assignation manuelle des vols de Romain aux pilotes — illégale ; (B) mise en jeu automatique — même problème ; faire payer le prix affiché plein au client sur un vol pilote — illégal ; faire porter au pilote une vraie part sur les vols de Romain — non viable (Romain lui-même ne porte pas sa part, sa « contribution » = frais annuels type GPS).
Conséquences
Blocs B/C/D construits mais gelés (branche espace-pilote-wip). Plan HTML réécrit : sections « Audit & plan de reprise » + « Chantier Option 3 ». Validation avocat/DGTA requise avant d'ouvrir à un vrai pilote.

2026-09-08 · Espace pilote — annulée le jour même

Modèle A — le pilote encaisse en direct

Contexte
Trancher qui encaisse sur un vol confié à un pilote : le pilote (modèle A) ou Romain qui reverse ensuite (modèle B).
Décision (matin)
Modèle A : QR SEPA + virement/Payconiq directement au pilote, rien par le Stripe de Romain, 0 € dans la P&L, reçu émis par le pilote. Bloc D codé sur cette base.
Annulation (soir)
La question « comment afficher le prix quand un pilote vole » a fait remonter le blocage légal plus profond → pivot Option 3 (décision ci-dessus).
Alternatives écartées
Modèle B (Stripe Romain + reversement IBAN au pilote) — zone grise PSD2 (exemption « agent commercial » douteuse pour un intermédiaire) + compta pass-through jamais vérifiée.

2026-09-07 · Espace pilote

Routage des emails pilote sans adresse dédiée

Contexte
Un pilote doit pouvoir échanger avec le client sans casser le branding Fly Horizons ni exposer son email perso.
Décision
Pas d'alias par pilote, pas de forwarding. Tout part de Fly Horizons <info@fly-horizons.com>, le nom du pilote dans le corps du message. Le pilote écrit depuis le fil de ticket dans /pilote, l'app envoie à sa place, cousu au même thread email (References / In-Reply-To). Réponses client captées par un webhook /api/inbound-email sur un sous-domaine reply.fly-horizons.com.
Alternatives écartées
Alias Namecheap par pilote (abandonné) ; forwarding classique.

2026-09-06 · Espace pilote

Vérification pilote déclarative mais bloquante

Contexte
Quel niveau de contrôle sur les licences / certificats médicaux des pilotes avant qu'ils puissent opérer.
Décision
Déclaratif : champs texte + dates (n° de licence, expiration licence, expiration medical, ratings), pas d'upload de PDF en v1 — mais bloquant : tant que non rempli ou périmé, badge rouge et le pilote ne peut rien faire. Charte pilote signée via popup scroll-to-accept, preuve (version + horodatage) conservée.
Alternatives écartées
Upload de documents obligatoire dès la v1 (trop lourd) ; aucun contrôle (trop risqué).
